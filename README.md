# why.inbokss.com

Static site served by GitHub Pages at **https://why.inbokss.com** (see `CNAME`).

| URL | Page |
| --- | --- |
| `/`, `/en/`, `/ru/`, `/lt/`, `/et/` | Landing page "Why Inbox.lv" (Latvian is the default, served at `/`) |
| `/themes/`, `/en/themes/`, … | Vote for the new Inbox Mail colour themes |
| `/themes/stats/` | Live aggregate vote statistics (English only) |
| `/inbox-survey/` | Inbox.lv user survey (not indexed by search engines) |
| `/youth-portal/` | Feedback form for the new youth portal prototype (Latvian, not indexed) |
| `/youth-portal/stats/` | Live statistics for that form, refreshed every 3 s (comments need the stats key) |
| `/gaismasaptauja/` | Gaismas dārza date poll: name and one date only (Latvian, not indexed) |
| `/gaismasaptauja/stats/` | Live votes per date (public, refreshed every minute); names only after entering the stats key |

## Editing

All page text lives in `src/i18n/<lang>.json`; the HTML templates are in `build.py`.
After any change, regenerate the pages and commit the generated files together with the sources:

```bash
python build.py
```

The build writes every `index.html`, `sitemap.xml`, `robots.txt` and `llms.txt`.
Do not edit the generated `index.html` files by hand.

| File | Purpose |
| --- | --- |
| `assets/header.css`, `assets/header.js` | Shared inbox.lv-style header (both pages), fonts |
| `assets/site.css` | Landing page styles |
| `themes/themes.css`, `themes/app.js` | Theme picker and demo mailbox |
| `themes/poll.js`, `themes/config.js` | Vote submission to Supabase (publishable key only) |
| `*.sql` | Supabase schema, migrations and checks |
| `gaismasaptauja/`, `gaismasaptauja.sql` | Gaismas dārza poll and stats pages (hand-written, not part of `build.py`) and their Supabase table and functions; the SQL is run once in the Supabase SQL editor (publishable key only in the browser). |
| `inbox-survey/` | The user survey. Generated by `npm run build:why` in [ingmarsj/inbox-survey](https://github.com/ingmarsj/inbox-survey); do not edit by hand. Answers are stored in the `survey_*` tables of the same Supabase project (publishable key only). |

## Tests (Gaismas dārza poll)

| Command | What it checks |
| --- | --- |
| `cd tests/gaismasaptauja && npm install && npm test` | The vote page and the stats page in a fake browser (jsdom) with a fake Supabase: validation, saving, error messages, double clicks, blocked storage, the stats key flow, XSS, plus checks that the pages, `themes/config.js` and `gaismasaptauja.sql` agree (dates, function names and parameters, CSP, name length). |
| paste `gaismasaptauja.test.sql` into the Supabase SQL editor and run it | The database rules (one answer per browser, name protection, cleaning, key-gated names, anon permissions, rate limit, 1000 cap, upgrade from the first version). It rolls everything back: `PASS: all N checks passed` appears as an error message; real data is never changed. |

## SEO and AI discovery

Each page has its own title and description, a canonical URL, `hreflang` alternates (with `x-default` → Latvian),
Open Graph tags, and JSON-LD (Organization, WebSite/WebPage, MobileApplication, BreadcrumbList).
`sitemap.xml` lists every language version with alternates; `llms.txt` summarises the site for AI assistants.

## Local preview

```bash
python -m http.server 8790
```

Then open http://localhost:8790/. Note that submitting a vote locally records a real vote in Supabase.
